# Безопасность · Security

## Сообщить об уязвимости

Tethered хранит личные данные пар. Нашли уязвимость — сообщите **приватно**,
не публичным issue: вкладка **Security → Report a vulnerability** этого
репозитория (GitHub Private Vulnerability Reporting).

Опишите, что можно сделать, шаги воспроизведения и версию приложения или
коммит сервера. Ответим и согласуем срок раскрытия.

*Found a vulnerability? Please report it privately via the repository's
**Security → Report a vulnerability** tab, not via a public issue.*

## Что входит

- приложение (`lib/`, `android/`, `ios/`) и его E2E-шифрование (`lib/fork/e2e/`, [docs/E2E.md](docs/E2E.md));
- сервер (`server/`) и JS-хуки, которые он собирает;
- конфигурация развёртывания (`deploy/`).

Не входит: чужие инстансы и их данные, DoS, уязвимости сторонних зависимостей
(о них — их авторам).

## Модель угроз

Сервер считается любопытным: он не должен читать содержимое пары. Что он видит
открыто и почему — [docs/E2E.md](docs/E2E.md), §2–3. Находка, после которой
сервер или посторонний читает или подделывает данные пары, — критическая.

## Что не секрет

- DSN крашрепортов (Bugsink) — публичный ключ приёма, он в клиенте намеренно;
  отчёты уходят только с согласия и без личных данных.
- Адрес сервера в сборке — он есть в каждой установленной копии.

Настоящие секреты (ключи подписи, ключ API Centrifugo, сервисный аккаунт FCM,
пароли) в репозиторий не попадают: только секреты CI и env сервера.
