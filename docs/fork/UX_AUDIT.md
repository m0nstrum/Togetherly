# UX-аудит фич (22.10.2026)

Источник: тест владельца на двух телефонах и восемь агентов-аудиторов, которые
прошли сценарии по коду (приложение не запускали). Каждая находка — гипотеза,
пока не стоит «подтверждено»: перед правкой её проверяют по коду заново.

Статусы: **из аудита** — не перепроверено; **подтверждено** — проверено по
коду; **исправлено** — с коммитом; **отклонено** — с причиной; **позже** —
сознательно отложено.

Волны: **1** — потеря данных, приватность, безопасность; **2** — видимое
состояние (интерфейс врёт или молчит); **3** — навигация и хвосты апстрима.

## Общий диагноз

Интерфейс показывает намерение, а не факт, и молчит об изменениях:

- ошибки глотаются: `catch` без сообщения, `null`/`[]`/`false` вместо причины,
  экран принимает это за успех или пустоту;
- состояние рисуется по нажатию, а не по источнику (галочка до отправки, «плей»
  по тапу, переключатель «включено» без передачи, одно «Звоним…» на все
  стадии);
- о смене состояния не сообщают (партнёр вышел, связь пропала, часть файлов
  не залилась, бэкап перезаписан).

Лечение — общие кирпичики в `lib/fork/ui/`, затем волны:

- **Результат действия**: сервис отвечает «ок» или «нет, причина» (сеть,
  сессия, нет ключа, размер, отказ сервера), а не `null`/`true`.
- **Одно сообщение об ошибке**: человеческий текст причины + «Повторить»,
  никаких `Exception: …` на экране.
- **Плашка состояния** живых экранов (комната, лента, звонок, карта): что
  происходит сейчас, не исчезает через 2 секунды.
- **Правило**: интерфейс показывает факт из источника (плеер, сокет, очередь),
  а не то, что нажали. В `lib/fork` — сторож на `catch` без сообщения.
